# Skillet — v1 Intent

_Product name: **Skillet** ("Skillet — the AI engineer's cookbook"). "skill" + a
kitchen pan; the literal tagline carries SEO while the name stays ownable._

_Confirmed via interview, 2026-09-09. This is the intent the spec consumes; it is not the spec._

## Outcome

A polished open-source web app where beginner AI engineers learn AI-engineering
concepts by reading *real* recipe source and running it live. Recipes are grouped
by theme and ordered basic → advanced within each group.

## User

Beginners who know Python basics but have never built RAG / agents / evals.
Primary driver is **reach** (help as many people as possible); a portfolio
trophy for the author is a welcome secondary benefit. A polished, uncluttered,
subtly animated UI is in service of reach — it aids retention and learnability.

## Why now

The author has learned this material and found it teaches far better as a
hands-on app than as prose, and wants it in front of as many people as possible.

## Success

A first-time visitor lands on the hosted URL and runs their first recipe with
**zero setup**: keyless trial using the author's API key, capped at ~1–2 recipe
runs/day, behind a global spend kill-switch. After that they either add their own
API key to keep going, or clone the repo (`uv` **or** Docker — both first-class)
to run everything locally without limits.

## Binding constraint

The author's time — specifically authoring genuinely good, pedagogically-ordered
recipes (clear explanation + clean code + use-case examples). Therefore v1 ships
**few recipes (3–4)** but a **rock-solid recipe framework**:

- One Python module per recipe.
- The backend executes that module; the UI displays that same file byte-for-byte.
  True 1-to-1 mapping, single source of truth, no copy, no drift.
- Recipes are structured to be both readable and directly executable with
  UI-injected parameters.
- Global settings (e.g. model-provider API keys) that recipes inherit and can
  override per-recipe. If a recipe does not set an env var, the global default is
  used and the UI notes it was inherited from global.

## v1 scope — IN

- Hosted demo (backend on Render free tier, frontend on Vercel free tier).
- Rate limiting on hosted execution: IP + signed cookie, counter in Upstash Redis
  (`INCR` + `EXPIRE`). Casual limiting only — determined bypassers should just
  clone the repo, which is the desired outcome.
- Keyless trial: author's key, ~1–2 runs/day/user, hard global daily spend cap
  with kill-switch. Then "add your own key" or "clone locally".
- BYOK: user API keys accepted per-request, used, discarded. Never persisted
  server-side. This is a visible, stated security property.
- 3–4 recipes across 2–3 groups (specific recipes TBD in spec).
- Browse all recipes freely (description, use cases, examples, source) regardless
  of run limits.
- Local clone: one-command start via `uv` AND via Docker. Both first-class.
- Multiple recipe tabs open at once (RunJS-style).
- Settings: global defaults + per-recipe override/inheritance behavior.
- Progress tracking in browser localStorage (per-device).
- Streaming execution output (SSE) — show tokens/steps live, not a spinner.
- OpenAI-desktop look and feel. PWA (installable, offline shell). MIT license.
- Users can point the frontend at a custom backend URL.
- Single monorepo (`backend/` + `frontend/`), not split repos — one-command
  Docker Compose start.
- Frontend toolchain: **bun** (package manager + runtime + script runner).
  Backend: **uv**.

## v1 scope — OUT (explicitly deferred)

- Accounts / login.
- Server-side or cross-device progress sync (revisit when accounts land — that is
  when cross-device sync becomes real).
- Electron / native desktop packaging (PWA only for v1).
- Cross-group linear curriculum path (groups are ordered internally; no single
  path across groups).
- Rust (stack is locked: Next.js + shadcn/ui + Tailwind frontend, FastAPI backend).
- Local embedding models / heavy vector DB in the hosted runtime (512MB RAM on
  Render free) — hosted RAG uses API embeddings + lightweight in-request store.
  The local clone may be heavier.

## Recipe content principles

- **Default teaching stack: LangChain / LangGraph** — it's the most popular
  framework, so beginners benefit most from learning it. Use it wherever it fits.
- Other frameworks (Google ADK, CrewAI, etc.) are used where they're genuinely
  the better fit for the concept being taught, not by default.
- Where a framework's abstractions would hide the fundamental being taught, a
  group may open with a "from scratch" recipe before the framework version
  (decided per group in the recipe mini-specs, not mandated here).

## Build order

Frontend first, with sample data, iterated until it looks right. Then the backend.

## Known hosting caveats (accepted)

- Render free tier spins down after ~15 min idle → ~50s cold start on the first
  hit. Mitigate with a "waking up" loading state and/or a keep-warm ping.
- Render free tier: 512MB RAM, 750 instance-hours/month.
